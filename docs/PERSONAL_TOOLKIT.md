# Личные инструменты Mados

Личные инструменты версии 0.42.0. Новые функции работают через настоящий C# worker, без изменений серверной авторизации. Состав релиза описан в [заметках к версии 0.42.0](releases/v0.42.0.md); ниже сохранены результаты проверки при разработке.

## Где находятся функции

| Функция | Место в интерфейсе | Поведение |
|---|---|---|
| Перенос игрового кэша | Инструменты → Хранилище → Игры на другом диске | Выбор папки, подтверждение, копирование и проверка SHA256, отмена, перезапуск. Исходная копия удаляется только после проверки при следующем запуске. |
| Мой Mados | Инструменты → Мой Mados | Экспорт `.mados-backup`, предпросмотр и выбор разделов при восстановлении. Совпадения объединяются по нормализованному адресу. |
| Реплеи и бандлы | Инструменты → Реплеи | Добавление ZIP через диалог или перетаскиванием, поиск, название, заметка, отметка просмотра и запуск через существующий механизм контент-бандлов. |
| Поведение окна | Настройки → Внешний вид | «Сворачивать при запуске игры» и «Вернуться в Mados после игры». Обе настройки изначально выключены, учитывается реальный ClientRunning. |
| Ожидание места | Описание сервера → Ждать место | Один сервер, проверка раз в 30 секунд до 30 минут. Уведомление внутри лаунчера; место не резервируется, автоматического подключения нет. |

## Данные и восстановление

- Перенос касается только `engines`, `modules`, `content.db`, `override_assets.db`. Аккаунты, локальные серверы, реплеи и настройки не перемещаются. На время переноса запуск заблокирован. Фоновые сезонные ресурсы приостанавливаются, базы проходят checkpoint перед копированием.
- Новый кэш включается через атомарное обновление `migration-v1.json`. До перезапуска прежние файлы сохраняются. Если после отложенной очистки новый кэш успел измениться, старые файлы сохраняются, журнал переименовывается в `.retained-*` и UI показывает предупреждение; следующий перенос остаётся доступным.
- При неудачной копии исходный кэш остаётся рабочим. Для ручного восстановления после повреждения нового диска: закрыть лаунчер, проверить целостность сохранённой старой копии, вернуть `CacheUser`/`CacheLocal` из журнала переноса в `migration-v1.json`. Не удалять файлы вручную, пока не проверен запуск.
- Архив содержит избранное, профили, заметки и строго ограниченное оформление: тему, уменьшение движения, sidebar, главную и группы избранного. Пароли, токены, аккаунты, история игры, файловые пути и произвольный localStorage не экспортируются. Лимит файла — 4 МиБ; превышение проверяется до записи и до применения восстановления.
- Избранное остаётся общим, как в существующем лаунчере; профили, заметки и реплеи разделяются по аккаунтам. Предпросмотр привязан к аккаунту и действителен 10 минут.
- Перед восстановлением создаётся полная копия состояния текущего аккаунта. Кнопка «Сохранить копию до восстановления» экспортирует её для обычного импорта. Изменения в разных SQLite-базах не являются одной общей транзакцией: при сбое показывается ошибка, восстановление не объявляется успешным; исходная копия остаётся доступной. Ошибка записи избранного откатывает также его состояние в памяти.
- `replay-library.db` содержит только индекс файлов и пользовательские метки. Удаление записи не удаляет ZIP. Изменённый или перемещённый ZIP требуется добавить повторно. Проверяется ограниченный по размеру `rt_content_bundle.json`; импорт библиотеки ничего не распаковывает.
- Наблюдение останавливается при смене аккаунта, начале подключения и закрытии worker. Отсутствующий лимит игроков означает «Сервер не сообщает лимит», а не свободное место.

## Архитектура и контракты

```text
React → ограниченный preload → Electron main → JSON-RPC → C# worker
                                ├─ нативные диалоги и разрешения на выбранные пути
                                ├─ архив оформления и резервная копия
                                └─ политика сворачивания / восстановления окна
Worker: CacheTransfer + ReplayLibrary + SeatWatch + PersonalData
        существующие accounts / favorites / profiles / notes / notifications
```

Контракт: `Mados.Launcher/src/contracts/launcher.ts`, `schema.ts`, `ipc.schema.json`; формат архива: `personal-archive.ts`.
Новые группы: `cache.*`, `replays.*`, `personal.*`, `seatWatch.*`; события `cache.progress`, `seatWatch.updated`, уведомление `server-slot`. Внутренние `personal.snapshot`/`personal.apply` доступны только main → worker, в renderer allowlist их нет.

## Проверка и сборка

Автоматические проверки: 171 TypeScript-тест и 101 C#-тест, typecheck. Проверены native grants, разделение аккаунтов, строгая схема архивов, размер, нормализация адресов, перенос и отложенная очистка, replay metadata и удаление только индекса, таймаут и отмена наблюдения, политика окна.

Реальный worker smoke использует отдельный каталог с заранее созданным migration marker, две локальные тестовые учётные записи с истёкшими токенами и HTTP `/status` на loopback. Проверяет SQLite, восстановление с принудительной ошибкой записи, отсутствие дубликатов избранного, разделение аккаунтов, уведомление, перенос и новый запуск. Пользовательские данные не используются.

UI smoke в Electron использует только тестовые фикстуры и проверяет новые экраны, подтверждения, темы, 800×600, reduced motion ОС/приложения. Скриншоты: `artifacts/interface-preview/toolkit-*.png`. Это визуальная проверка, не доказательство сетевого входа в игру.

В Windows Debug-пакет включены self-contained `Mados.Worker` и `SS14.Loader`, оба с `--configuration Debug --runtime win-x64`. Vite собирает renderer в обычный упакованный bundle. Приложение unsigned; версия пакета не повышалась.

```powershell
cd Mados.Launcher
npm run typecheck
npm test
npm run build
$env:MADOS_WORKER_CONFIGURATION='Debug'
$env:MADOS_WORKER_RID='win-x64'
npm run prepare-worker
npx --no-install electron-builder --win --x64 --dir --publish never --config.directories.output=../artifacts/mados-debug-personal-toolkit
```

Сборка: `artifacts/mados-debug-personal-toolkit/win-unpacked/Mados Launcher.exe`. EXE запускается вместе с соседними файлами и каталогом `resources`.

Ограничения проверки: полноценный вход на публичный игровой сервер, реальное воспроизведение пользовательского реплея и переключение окон после реальной игры в этой задаче не выполнялись. Политика окна проверена автоматическими тестами; нативный smoke проверяет запуск и штатное закрытие пакета. Сохраняются прежние предупреждения зависимостей NU1903 и предупреждение Vite о размере bundle.


Итоговый native smoke: пакет запускается, работает ровно один bundled worker, штатное закрытие возвращает код 0, дочерних процессов не остаётся. Хеши Worker/Loader совпадают с Debug DLL из `bin/Debug/net10.0/win-x64`. Подтверждение: `artifacts/mados-debug-personal-toolkit/build-verification.json` и `native-smoke/report.json`.
